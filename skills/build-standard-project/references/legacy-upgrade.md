# Legacy project upgrade

Installing a newer Skill does not rewrite an existing project's root `AGENTS.md`, `package.json`, or CI workflow. Projects originally generated by v1.1-v1.6 can therefore keep running requirement validation, coverage, fingerprints, AI review, browser suites, and `quality:full` for a small Bug even after the global Skill is upgraded.

Use this route only when the user explicitly asks to migrate or upgrade an existing generated project. First inspect without writing:

```text
python <build-standard-project-skill-root>/scripts/migrate_legacy_project.py --project <project-root>
```

If the plan identifies the known generated legacy template and preserves the project's custom rules, apply it explicitly:

```text
python <build-standard-project-skill-root>/scripts/migrate_legacy_project.py --project <project-root> --apply
```

The migration updates only the generated root policy, root quality scripts, lightweight change tracking, and the known Quality workflow. It does not delete product code or archival documents. It refuses to overwrite an unrecognized/custom `AGENTS.md`.

After applying, review the diff and run one directly affected test file. Do not run `quality`, `quality:full`, coverage, E2E, visual, deployment, or independent review merely to validate the migration.
